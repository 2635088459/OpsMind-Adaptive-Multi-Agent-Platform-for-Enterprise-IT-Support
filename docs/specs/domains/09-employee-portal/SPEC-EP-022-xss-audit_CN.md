# SPEC-EP-022 — XSS Audit（XSS 审计）

> Domain: `09-employee-portal` | Phase: 08 — 安全与发布加固 | 状态：Implemented

## 1. Spec 身份
`SPEC-EP-022`，针对本 domain 特有的高风险面——渲染 LLM 生成内容和用户上传内容——的一次安全加固审计。

## 2. 目标
确认没有任何 agent 生成的消息内容、转人工通知文本或附件文件名能在员工浏览器中执行脚本——这是整个 domain 中风险最高的一面，因为 agent 输出天然比典型的后端校验数据更不可信。

## 3. 设计依据
`11-security-and-authorization` §4（内容渲染安全）。

## 4. Actor
不适用——一个安全审计活动。

## 5. 范围
所有渲染 agent 消息内容、转人工文本或附件文件名的地方（SPEC-EP-005、SPEC-EP-007、SPEC-EP-012，以及来自 SPEC-EP-010 的附件列表）。

## 6. 非目标
服务端消毒（属于各自后端 domain）——本 spec 验证前端自身的渲染层从不信任这些来源的原始 HTML，作为纵深防御，无论后端行为如何。

## 7. 前置条件
相关 spec 已实现。

## 8. 输入
对抗性测试 fixture：包含 `<script>`/事件处理器负载的消息内容，包含类 HTML/脚本字符串的文件名。

## 9. 详细行为
确认所有 agent/转人工文本都作为纯文本渲染（或通过一个禁用脚本执行的 markdown 渲染器），从不对未消毒输入使用 `dangerouslySetInnerHTML`；确认附件文件名作为文本节点渲染，从不未转义地插入 HTML/URL。

## 10. 交互状态迁移
不适用。

## 11. 业务不变量
一条新的横切不变量：任何来自 LLM、其他用户或文件自身元数据的数据，都绝不作为可执行的 HTML/脚本渲染。

## 12. 幂等策略
不适用。

## 13. 消费/依赖的契约
不适用——这是一次渲染层审计，不是一个新的契约消费者。

## 14. 安全
本 spec 的全部内容都是安全关切；鉴于"与 LLM 聊天"这种产品面，这明确是 domain 09 安全阶段中优先级最高的单个 spec。

## 15. 可观测性
不适用。

## 16. 错误场景
任何发现的 XSS 向量都是一个待修复项，在本 spec 关闭前被跟踪并修复——不延后。

## 17. 验收场景
一个包含 `<img src=x onerror=alert(1)>` 的消息 fixture，在 UI 中任何可能出现的地方都渲染为无害文本。

## 18. 先写测试
一套组件测试，把每个对抗性 fixture 渲染到每个内容渲染面（SPEC-EP-005、007、010、012），断言无脚本执行、无未转义 HTML 注入。

## 19. 完成定义
所有对抗性 fixture 在应用的每个渲染面上都零脚本执行地通过。
