# SPEC-SC-016 — Concurrent Triage Conflict（并发分诊冲突）

> Domain: `10-support-console` | Phase: 07 — 并发加固 | 状态：Spec Planning

## 1. Spec 身份
`SPEC-SC-016`，一个针对性的强化 spec，把 SPEC-SC-013 的共享冲突处理工具专门应用到分诊流程，覆盖一个本 domain 独有的场景：agent（AI）本身可能通过 `SPEC-ARO-041` 与人工手动分诊尝试并发地重新分诊同一个工单。

## 2. 目标
证明当 `agent-runtime-service` 自己的转人工分诊调用（不只是另一个人类）与之并发到达时，SPEC-SC-010 的分诊表单能正确展示冲突。

## 3. 设计依据
`10-error-handling-and-reconciliation` §2；SPEC-SC-010；SPEC-SC-013；`SPEC-ARO-041`（后端自己调用分诊的路径）。

## 4. Actor
在 `agent-runtime-service` 作为转人工一部分也调用同一分诊端点的确切时刻，正在手动分诊同一工单的坐席。

## 5. 范围
一个针对这个特定"人类 vs. agent"竞态的专门测试场景（以及任何需要的 UI 文案调整），与"人类 vs. 人类"竞态（已被 SPEC-SC-013 通用覆盖）区分开。

## 6. 非目标
任何新的后端锁定/排序保证（domain 02 已有的乐观并发控制，已真实存在，是唯一的强制机制——本 spec 只是验证控制台针对它的客户端行为）。

## 7. 前置条件
一个工单正处于转人工中途（一次 agent-runtime-service 的分诊调用正在进行），同时一个人类也提交了 SPEC-SC-010 的表单。

## 8. 输入
与 SPEC-SC-010 相同，处于这个特定时序场景下。

## 9. 详细行为
无论哪个调用第二个到达 domain 02，都会收到版本冲突响应；SPEC-SC-013 的共享处理器如实渲染实际生效的分诊结果（可能来自 agent，而非该人类）。

## 10. 交互状态迁移
完全委托给 SPEC-SC-013 的冲突恢复流程。

## 11. 业务不变量
BI-SC-005，专门针对"agent vs. 人类"竞态而非只是"人类 vs. 人类"进行验证——这是本 domain 自己 LLD 中该不变量声明的完整范围。

## 12. 幂等策略
与 SPEC-SC-010/013 相同。

## 13. 消费/依赖的契约
与 SPEC-SC-010 相同，并与 `SPEC-ARO-041` 自己的分诊调用一同被验证。

## 14. 安全
除 SPEC-SC-010 自身要求外不适用。

## 15. 可观测性
该冲突事件的 trace 理想情况下应展示两个竞争调用的 span，以便事后分析（一个加分项，不是本 spec 的硬性要求）。

## 16. 错误场景
本 spec 的全部内容就是被验证的错误场景。

## 17. 验收场景
模拟一次 agent 分诊调用先到达的竞态，会通过冲突 UI 向人类坐席展示 AI 判定的分诊结果，而不是一个通用错误。

## 18. 先写测试
针对一个 mock/真实的 domain 02 端点，模拟两个调用竞态的集成风格测试。

## 19. 完成定义
"agent vs. 人类"竞态被证明能通过已有的冲突处理 UI 正确解决，无需在 SPEC-SC-013 已提供的基础上做任何特殊处理。
